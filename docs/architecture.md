# Архитектура

1. FastAPI обслуживает REST, OPDS и собранный React. PostgreSQL хранит пользователей, библиотеки, произведения, издания, файлы, задачи и позиции чтения.
2. Managed получает неизменяемые оригиналы по SHA-256 в отдельном томе. Indexed хранит относительные пути внутри read-only монтирования. Обложки и результаты конвертации находятся в отдельном каталоге тома.
3. Веб-загрузка, сканирование и OPDS используют одну операцию импорта. PostgreSQL хранит очередь и журнал задач. После записи задачи в PostgreSQL API отправляет короткий сигнал через Redis, чтобы разбудить обработчик. При отсутствии сигнала обработчик опрашивает очередь в PostgreSQL.
4. Веб-читалка сохраняет локатор конкретного файла с ожидаемой версией. Конфликт HTTP 409 возвращает позицию сервера для выбора. OPDS выдаёт только навигацию и файлы.
5. Внешние каталоги используют собственный HTTP-транспорт с закреплением проверенного IP при соединении. Авторизация источника привязана к origin. Ссылки на скачивание берутся из каталога.

HTTP-контракт опубликован в OpenAPI. Спецификации [OPDS 1.2](https://specs.opds.io/opds-1.2), [OPDS 2.0](https://specs.opds.io/opds-2.0) и [KOReader Sync](https://github.com/koreader/koreader-sync-server) используются для внешних интерфейсов. KOSync требует отдельной привязки идентификатора документа к файлу и хранения исходного локатора клиента.

Язык веб-интерфейса хранится в браузере. По умолчанию используется русский. В `frontend/src/locale.en.ts` находятся английские переводы интерфейса, а в `frontend/src/locale.server.en.ts` — сообщения API и фоновых задач. Интерфейс переводит сообщения при отображении, поэтому переключение языка не меняет API и сохранённые данные. Названия и содержимое книг, а также тексты внешних каталогов отображаются на языке источника.

## Личные данные

Состояние произведения хранится по паре пользователь и произведение. Точные позиции и выделения привязаны к файлу, поскольку CFI и координаты других форматов зависят от издания. Для EPUB вместе с позицией сохраняется название текущей главы из оглавления. Сохранение позиции и обновление личного состояния проходят в одной транзакции. Прежние позиции браузеров переносятся в личное состояние с последним устройством при миграции.

При открытии другого файла читалка может предложить переход по более свежему проценту чтения этого произведения. Пользователь подтверждает приблизительный переход. Каждый файл хранит собственный точный локатор.

Учётная запись «Только чтение» может менять свои закладки, коллекции и прогресс. Право на запись в общую библиотеку проверяется отдельно для REST и перед исполнением фоновой задачи. Смена пароля заменяет текущий веб-сеанс и завершает остальные. Административный сброс завершает все веб-сеансы пользователя и отзывает его учётные данные для внешних клиентов.

## Управляемые файлы

Оригинал хранится по SHA-256. Раскладка создаёт отдельный снимок с манифестом под идентификатором фоновой задачи. Блокировка библиотеки фиксирует набор файлов и метаданные между последней проверкой плана и публикацией снимка. Указатель активной версии и статус задачи сохраняются одной транзакцией.

Корзина меняет видимость произведения. Записи о файлах, изданиях, чтении и происхождении сохраняются. При пофайловом импорте идентификатор новой записи и учёт обработанного файла сохраняются в журнале вместе с записью книги. Повторный запуск продолжает со следующего подтверждённого файла.

## Производительность каталога

Страницы каталога и выдача OPDS по жанру отбираются в БД. PostgreSQL использует индексы JSONB для жанров и меток. Миграция добавляет индексы `pg_trgm` для поиска по метаданным и псевдонимам авторов при наличии расширения и прав на его подключение. Поиск сохраняет правила нормализации и сопоставления по подстроке. [Индексы pg_trgm](https://www.postgresql.org/docs/17/pgtrgm.html#PGTRGM-INDEX)

Веб-каталог и OPDS используют общий дисковый кэш миниатюр. Обложка может храниться в кэше клиента. При повторном запросе сервер заново проверяет права на книгу и возвращает `304` без изображения, если версия обложки совпадает. [Условные HTTP-запросы](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.2)

Для воспроизведения замера запустите команды в отдельном окне PowerShell из корня проекта. Проект `polka-bench` создаёт синтетические карточки, издания, связи с авторами и записи файлов. Замер покрывает запросы каталога и OPDS. Фактическое чтение файлов и массовый импорт проверяются другими сценариями.

На локальном Docker с PostgreSQL 17 и 30 000 карточек получили следующие медианы. Для каждого запроса выполнено 12 измерений после первого прогрева. Время включает обработку HTTP и сериализацию ответа.

| Запрос | До, мс | После, мс |
|---|---:|---:|
| Страница OPDS по жанру | 1 482 | 68 |
| Поиск отдельной книги по части названия | 289 | 26 |
| Поиск по метаданным и псевдониму | 49 | 31 |
| Список фильтров каталога | 552 | 151 |
