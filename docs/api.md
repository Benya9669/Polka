# REST API

Машиночитаемая спецификация доступна по `/openapi.json`. Основной префикс `/api/v1`. После входа браузер получает cookie `ebook_session` с флагом HttpOnly. Для API OPDS используйте выданный OPDS-токен.

| Группа | Основные методы |
|---|---|
| Авторизация | `GET /auth/status`, `POST /auth/setup`, `POST /auth/login`, `GET /auth/me`, `POST /auth/logout` |
| Доступ | `POST /auth/users`, `GET /auth/opds-tokens`, `POST /auth/opds-tokens`, `DELETE /auth/opds-tokens/{id}` |
| Библиотеки | `GET /libraries`, `POST /libraries`, `PATCH /libraries/{id}`, `POST /libraries/{id}/upload`, `POST /libraries/{id}/scan` |
| Каталог | `GET /books`, `GET /books/{id}`, `PUT /books/{id}`, `GET /files/{id}` |
| Авторы | `GET /authors`, `GET /authors/{id}`, `PUT /authors/{id}`, `POST /authors/{id}/aliases`, `DELETE /authors/{id}/aliases/{key}` |
| Серии | `GET /series`, `GET /series/{id}` |
| Импорт | `GET /imports`, `POST /imports/{id}/confirm`, `POST /conversions/{id}` |
| Чтение | `GET /reading/progress/{file_id}`, `PUT /reading/progress/{file_id}`, `GET /reading/history`, `GET /reading/bookmarks/{file_id}` |
| OPDS-клиент | `/opds/sources`, `/opds/sources/{id}/test`, `/opds/sources/{id}/browse`, `/opds/sources/{id}/search`, `/opds/search`, `/opds/downloads` |

Администратор может отправить `{"url":"https://catalog.example/opds"}` в `POST /opds/sources/authentication`. Запрос обнаруживает объявленные способы входа без передачи учётных данных. Ответ содержит `secure`, `same_origin`, `protected` и документ с методами, подписями полей и доступными ссылками. Поле `document` равно `null`, если сервер не объявил способ входа.

Ответ `GET /opds/search?q=…` содержит `local.items` и результаты каждого активного источника в `remote`. Внешние публикации содержат `matches.local` со ссылками на пять последних доступных пользователю произведений, `matches.local_total` с числом совпадений и `matches.sources` с другими каталогами, где есть похожая запись. Совпадение названия и автора служит подсказкой. Для источника без OpenSearch или другого подходящего шаблона поиска возвращается `unsupported: true`. При недоступности или таймауте источника возвращается его `error`.

В ответе внешнего обозревателя `facets` содержит объявленные источником группы фильтров и сортировки. Вариант может содержать признак `active` и количество результатов `count`. Чтобы открыть вариант или страницу, отправьте значение `link`, `next` или `previous` из ответа в поле `link` запроса `POST /opds/sources/{id}/browse`.

`POST /opds/downloads/preview` принимает `source_id`, `library_id` и `link` из результата просмотра OPDS. В ответе перечислены кандидаты для объединения. `POST /opds/downloads` принимает те же поля и необязательные `work_id` и `read_after`. При выборе `work_id` скачанный файл повторно проверяется по фактическим метаданным. Для открытия читалки используйте `read_file_id` в результате завершённой загрузки. Для конвертируемого формата это поле заполняется после завершения задачи `conversion_id`.

Для скачивания без импорта отправьте `source_id`, `link` и `delivery: "file"` в `POST /opds/downloads`. После проверки временный файл доступен владельцу задачи через `GET /opds/downloads/{id}/file` до времени `expires_at`. До готовности маршрут отвечает HTTP 409, после истечения срока — HTTP 410.

При записи позиции передавайте `locator`, `percentage` от 0 до 1, `device` и текущую `version`. Для EPUB можно передать название текущей главы в `chapter`. Сервер возвращает `locator_type` со значением `epub_cfi` или `pdf_page`. Новая запись начинает с версии 0. HTTP 409 возвращает позицию сервера в `current`.

Если у читателя есть более свежая позиция в другом файле того же произведения, `GET /reading/progress/{file_id}` дополнительно возвращает `alternate` с ID исходного файла, форматом, процентом и датой. Читалка предлагает приблизительный переход и сохраняет точный локатор открытого файла после подтверждения. Задачи возвращают ID и статус, детали доступны через журнал импортов и менеджер загрузок.

Администратор читает и записывает расписание через `GET` и `PUT /libraries/{id}/scan-settings`. При записи передаются `mode` (`off`, `preview`, `apply`), `interval_minutes`, `watch`, `formats` и `folder`. Для индексируемой библиотеки используется её собственная папка. Ответ содержит `next_scan`, а отчёт о сканировании сообщает количество повторно использованных отпечатков в `reused`.

В `POST /imports/{id}/confirm` можно передать `choices`, где ключом служит путь файла из плана. Действие `skip` пропускает файл. Действие `work` принимает `work_id` из `matches`, а `incoming` принимает `path` из `incoming`. Без выбранного действия по умолчанию создаётся карточка или учитывается точный дубликат. Повторное подтверждение с другими решениями возвращает HTTP 409.

Личные коллекции доступны через `/collections`, а списки чтения и статистика через `/reading/states/{work_id}`, `/reading/shelf`, `/reading/home` и `/reading/sessions`. Заметки и выделения хранятся в `/reading/annotations/{file_id}`, экспорт данных доступен по `/reading/export`.

`GET /reading/sessions` возвращает сеансы чтения от новых к старым. Параметр `limit` задаёт размер выборки, по умолчанию 30. Параметр `offset` позволяет открыть предыдущие сеансы.

Роль «Только чтение» сохраняет доступ к разрешённым книгам и личным данным чтения. Изменение библиотек, метаданных и запуск импорта для этой роли закрыты. Пользователь может сменить пароль и завершить свои браузерные сеансы. Администратор может изменить роль другого пользователя и сбросить его пароль. Сброс отзывает браузерные сеансы, OPDS-токены и учётные данные KOSync.

Фильтры каталога доступны через `GET /books/facets` и параметры запроса `/books`. Для массовой правки используйте `PATCH /books/batch`, для метаданных одного издания — `PATCH /editions/{id}`. Запрос `POST /books/{id}/editions/upload` загружает новое издание или добавляет файл в указанное через `edition_id` издание. Управляемые записи перемещаются в корзину и восстанавливаются через `POST /books/{id}/trash` и `POST /books/{id}/restore`.

Владелец библиотеки или администратор может вызвать `POST /books/{target_id}/merge/preview` с `source_id`, затем подтвердить объединение через `POST /books/{target_id}/merge` с `source_id` и полученным `revision`. Обе карточки должны принадлежать одной библиотеке. При изменении плана сервер отвечает HTTP 409. После объединения `GET /books/{source_id}` возвращает основную карточку, а журнал операций содержит запись `merge`.

Список авторов принимает `q`, `library_id` и `page`. Поле `authors` в произведении содержит имена из карточки, а `author_credits` добавляет идентификаторы профилей и основные имена. Чтобы связать уже существующий профиль с другим как псевдоним, отправьте `name` и `merge_existing: true` от имени владельца библиотеки или администратора. По прежнему идентификатору профиля сервер возвращает итоговый профиль.

Список серий принимает `q`, `library_id`, `parent_id` и `page`. Карточка серии возвращает `children` и `books`, которые можно листать независимо через `children_page` и `page`. В `PUT /books/{id}` передайте `series_memberships` со списком объектов `{"path":["Серия","Подсерия"],"position":"2.5"}`. Пустой список удаляет членства карточки. `series` и `series_index` сохраняются как представление первой серии для прежних клиентов.

`PATCH /libraries/{id}` принимает `name`, `description` и `formats` от владельца или администратора. Поле `shared` может менять администратор. Поля, которых нет в запросе, сохраняют прежние значения. Пустой массив `formats` разрешает все поддерживаемые форматы оригиналов. `POST /libraries` принимает тот же массив при создании библиотеки.

В `/imports` результат задачи `scan` содержит `new_works` для числа новых карточек при выборе действий по умолчанию и `unreadable` для числа файлов, которые сервер не смог разобрать. Для точной копии поле `existing_duplicate` показывает, был ли файл уже в библиотеке при сканировании.

Планы раскладки и манифест находятся в `/libraries/{id}/layout`. Подтверждённый план создаёт фоновую задачу, состояние которой отображается в `/imports`. Отменить последний снимок можно только при совпадении его идентификатора с параметром `expected`.

`GET /libraries/{id}/layout` перечисляет доступные для удаления снимки в `removable_snapshots`. `DELETE /libraries/{id}/layout/snapshots/{snapshot_id}` удаляет копии и манифест и возвращает `204`. Повторный запрос для того же снимка также возвращает `204`. Для активного снимка и всех его предшественников возвращается `409`.

Раздел `/devices/sony` принимает список `file_ids` для предпросмотра через `POST /preview` и постановки пакета в очередь через `POST /exports`. Готовый ZIP скачивается через `GET /exports/{id}/archive`. Ручная позиция сохраняется через `PUT /progress/{file_id}` с процентом в долях от 0 до 1, страницей или признаком `finished`. Права на исходные книги проверяются при запуске задачи и при скачивании архива.

## KOReader

`GET /devices/koreader/files/{file_id}/match` ищет документ текущего пользователя по двоичному отпечатку выбранного файла. Поле `document` равно `null`, пока по этому отпечатку нет синхронизированной позиции. `linked_file_id` показывает существующую привязку. Сопоставление сохраняется отдельным запросом `PUT /devices/koreader/documents` с полями `document` и `file_id`.

`GET /devices/koreader/documents/{document}/history` возвращает до 50 последних принятых позиций текущего пользователя с исходным локатором `progress`, устройством и временем. Используйте `next_before` как параметр `before` для следующей страницы. `file_id` содержит привязку на момент отправки позиции и может быть `null`. Полная история входит в `koreader_history` при экспорте личных данных.
